# Finding Z provenance — draft for CIT review

Audit date: 2026-09-09. This document is an inventory, not a license grant or
certification that every file has been cleared for redistribution.

## Development history and original-material candidates

Finding Z was developed for PHYS 225A through instructor-directed, substantial
LLM-assisted implementation and iterative testing. This describes the development
process; it does not establish copyright ownership or license compatibility.

The application (`app.py`, `findingz/`), tests, scripts, configuration YAML,
notebook templates, and course documentation are candidates for the project's
own license after contributor/ownership review. Do not assume every line is
original merely because it was produced during this workflow. The present audit
does not include a comprehensive similarity search or a reconstruction of every
earlier project's contribution. Confirm any reused Higgs Lens or other project
material before representing these files as wholly original.

Update 2026-09-11: the instructor approved MIT for original project code,
notebooks, documentation, and synthetic teaching samples. LICENSE uses
"Prateek Agrawal, UCSB" as the attribution requested by the instructor.
Confirm the authorized copyright holder and institutional requirements before
publication. This attribution does not itself establish institutional authorization.
Third-party and adapted material retains its applicable upstream terms.

## Data and figures

`data/README.md` and `data/provenance.json` identify `signal.csv`, `background.csv`,
and `collision.csv` as synthetic teaching data generated by
`scripts/generate_demo_data.py` (documented seed 225), not ATLAS/CMS observations.
That provenance is documented, but regeneration/hash comparison has not been
performed for this audit. These legacy examples can be excluded from a minimal
release if the referencing legacy notebooks/catalog entries are also adjusted.

The LEP lineshape code in `findingz/lep.py` implements an illustrative calculation;
`scripts/export_lep_lineshape.py` exports its figures. It is not an imported LEP
measurement dataset. Review any additional images/materials added for release.

## Material supplied by upstream tools

The Dockerfile obtains MadGraph from its upstream repository and installs Pythia
and Delphes through MadGraph. Models, support libraries, detector cards, and
generated process code may contain upstream material and notices.

The course catalog selects Delphes CMS, ALEPH, and IDEA cards.
`findingz/hep_pipeline.py::render_delphes_card` preserves/adapts a selected
upstream card for the output profile; copied cards are not exclusively original
Finding Z material. Retain the upstream attribution and document modifications.

The `sm` and `loop_sm` entries refer to upstream models; `blackbox_1` is a disabled
catalog placeholder, not evidence of an installed or licensed custom UFO model.
Any later custom model needs its own provenance/license review.

Student runs, generated diagrams, copied cards, logs, and ROOT/LHE files are not
automatically covered by the application license. Review the actual contents
of any prepared sample selected for redistribution, particularly copied code/cards.
No blanket claim is made here that all numerical simulation output is subject to
the generator's license.
